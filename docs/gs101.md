# GS101 recovery

This is a separate Linux-only recovery path for Pixel 6 (`oriole`), Pixel 6 Pro
(`raven`) and Pixel 6a (`bluejay`). The author reports success with one bluejay
and two oriole devices. A raven profile exists, but no raven hardware success is
reported. Device condition, firmware versions and anti-rollback levels differ.

**Risks:** use only on a device you own or are authorized to repair. Recovery
and later flashing may cause data loss or permanent damage. Select the exact
model, inspect the code and profile, and use compatible firmware and
anti-rollback levels. No recovery or data preservation is guaranteed. This is
a community project, unaffiliated with Google or Samsung.

The method loads modified stages and changes verification-related checks. ABL
is modified to allow flashing when NOS/Titan M2 state is unavailable; its code
reports an unlocked state and non-production mode in the temporary environment.
Do not assume this is the device's persistent lock state, an official unlock,
or evidence that all security checks remain intact. Fastboot in RAM is not
itself permanent repair; flashing is a separate, potentially destructive step.

## USB access on Linux

From the project directory, install the included rule and reload udev:

```sh
sudo install -m 644 data/69-pixel-gs101.rules /etc/udev/rules.d/69-pixel-gs101.rules
sudo udevadm control --reload-rules
```

Disconnect and reconnect the phone. The rule grants access to USB devices
`18d1:4f00` (ROM recovery) and `18d1:4ee0` (fastboot) for the active local
desktop session using `uaccess`; it does not require running pixel-eub as root.
A tty-only rule does not grant the libusb backend access to the USB device.
For non-local or headless sessions, use an appropriate group-based rule for
your distribution. If the device is still not detected, check `lsusb`, the
cable, and the fresh-connection procedure.

## Start

Install Python 3.10+, gcc, libusb development headers, and Android
Platform-Tools. Install GTK 4, PyGObject and libadwaita 1.6 or newer for the GUI. Ensure your user can access the USB
device. The program does not automatically invoke sudo. The C backend is built
locally at start; it is not the precompiled binary in the archive.

Download [the GS101 profile archive](https://github.com/hurmichov/pixel-eub/releases/download/v1.0.1/pixel6_gs101_unbrick.zip), extract it, and select the appropriate
`pixel6_gs101_unbrick/devices/<codename>` folder, containing `metadata.json`.
Alternatively the included `python -m pixel_eub.gs101_prepare --help` can
prepare a profile from a local bootloader or factory ZIP (pass `--out-dir` to a
writable directory); its network downloads
and build compatibility require independent validation. Keep firmware out of
source control. Confirm redistribution rights before publishing firmware.

```sh
pixel-eub gui
pixel-eub gs101 --device bluejay --profile /path/to/devices/bluejay --acknowledge-risk
```

In the GTK dashboard select the phone model and its profile folder; Dry run checks the profile without opening USB. The GUI runs the same GS101 command. Disconnect all other fastboot devices;
the backend checks USB ID `18d1:4ee0`, not the identity of the phone. A
fastboot USB detection alone does not establish that the intended device was
recovered. It writes logs under `./logs`; remove private details before
sharing. Follow the archive's fresh USB connection instructions. To stop,
interrupt the CLI or close the GUI and confirm. No flashing is initiated by
this integration.
